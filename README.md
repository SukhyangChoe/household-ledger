# 우리집 가계부 v0.1

결제일 기준으로 수입·지출을 관리하고, 생활비 관리 계좌의 실제 잔액과 프로그램 계산 잔액을 맞추기 위한 웹 가계부의 첫 구현본입니다.

## 이번 버전에 들어간 것

- PC·모바일 반응형 대시보드 시안
- 월별 거래내역 화면
- 거래별 생활비 정산 필요 여부 계산
- 생활비 반영률 계산
- 정기 수입·지출·카드 할부 통합 규칙 구조
- Supabase 1차 데이터베이스 마이그레이션
- 핵심 계산 함수 단위 테스트

현재 화면은 **데모 데이터**로 실행됩니다. Supabase 연동과 실제 CRUD는 다음 개발 단계에서 연결합니다.

## 실행

Node.js 20.9 이상을 권장합니다.

```bash
npm install
npm run dev
```

브라우저에서 `http://localhost:3000`을 엽니다.

## Supabase 연결 준비

1. Supabase 프로젝트를 만듭니다.
2. `.env.example`을 `.env.local`로 복사합니다.
3. 프로젝트 URL과 Publishable Key를 입력합니다.
4. `supabase/migrations/202607250001_initial_schema.sql`을 적용합니다.

## 핵심 데이터 구조

- `accounts`: 계좌. 생활비 관리 계좌만 특별 표시
- `rate_rules`: 생활비 반영률과 변경 이력
- `categories`: 수입·지출 종류와 입력 자동값
- `cards`: 카드와 카드대금 출금 계좌
- `recurring_rules`: 정기 수입·정기 지출·카드 정기결제·할부 통합
- `transactions`: 실제 월별 수입·지출·자동 생성 거래
- `account_reconciliations`: 생활비 계좌 잔액 대조 기록
- `monthly_snapshots`: 월 마감 결과

## 확정된 운영 기준

- 카드 사용일과 가맹점은 기록하지 않습니다.
- 카드 지출은 실제 카드대금 결제일이 속한 달의 지출입니다.
- 모든 수입은 연결된 반영률 규칙에 따라 생활비 배정액을 계산합니다.
- 정산 필요 여부와 이체 방향은 별도 테이블 없이 거래 데이터에서 계산합니다.
- 정산 완료 시 거래의 `settlement_completed_at`만 기록합니다.
- 일반 정기결제와 할부는 같은 `recurring_rules` 구조를 사용합니다.
- 할부 회차는 시작월·종료월과 거래월을 기준으로 계산합니다.
